## 4. Findings

1. **Blocker. "The project" is never identified.** A/B: "the project team can see your data". C: "the people running the project can see your data". Name the organisation, people, country and pilot host, and say what is visible (posts, profile, who vouched for whom).
2. **Major. Warning not at the point of action.** C Join Gloki: "we will write to you when there is a place." B: "Before you start, we will tell you what the project can see." Put it beside every pilot sign-up, as A does.
3. **Major. Impersonation understated.** A/B: "anyone who has it can act as you." The node checks nobody. Use C's wording and say the consequence in the pilot warning: another member could post as you.
4. **Major. Vouching claimed ahead of status.** C: "Works in the app." A: "We are testing this now in the Gloki app." §5: the pilot's "people you choose" version has no server code. Only B says so. State what enforces the four vouches today.
5. **Major. B overclaims.** "Random choice matters: people making fake accounts cannot pick each other." §5 forbids a fake-account-resistance claim. Cut or caveat.
6. **Major. "No company or government is in charge" versus today.** One project-run server, a corporate host ("Young World Federalists, Inc.", country unstated). Add: today the project runs the only node.
7. **Major. Waitlist data under-specified.** C names no processor; A/B leave the newsletter question and privacy link open. Answer: where stored (country), how long, how often you write, whether the door choice is kept (it reveals who might host a node), any tracking, double opt-in (only B says "confirm").
8. **Major. B's protections table.** "Every record is copied to many members' servers, so nobody can change it quietly | Being built" clashes with the board's "Built, not yet tested". Eleven named technologies, mostly unbuilt, is the roadmap-as-product pattern. Fold into the board or cut.
9. **Major. Crypto smell undefended in A/B.** "Identity Block Chain", "partners", "consensus", "Carry the network", "it is what makes the node a blockchain". Page should answer: is there a token or coin, and who funds this? B's gap list names only BrightID among identity-proof projects.
10. **Minor. No code link in A or B** (C has a placeholder). Is the Gloki app itself open source, or only the node?
11. **Minor. Barlow quote.** A cypherpunk-libertarian manifesto beside "no government in charge". C's candour defuses it; A's less so.

## Audit commitment

As worded it is **empty**: it costs nothing until a vote is planned, "binding" and "independent" are undefined (A's "one whose result counts for real" is the only help), and the project alone decides what is binding. To make it credible:

- define "binding" (any vote whose result triggers action outside the app);
- state the scope (node, contracts, app, deployed configuration);
- say how the auditor is chosen and what "independent" means;
- promise to publish the full report, including unfixed findings, and re-audit after major changes;
- write it into the repository and the host organisation's governing papers;
- add: no vote of any kind while operators can read ballots.
